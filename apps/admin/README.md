# 投稿管理マニュアル（Admin）

投稿テンプレート機能（Post Setting）と投稿作成フローの運用手順をまとめています。テンプレートを利用するケースと、テンプレート無しの「デフォルトフォーム」双方を想定しています。画面はすべて `apps/admin`（SvelteKit 管理画面）で提供されます。

---

## 1. ナビゲーション

- 投稿設定一覧: `/post-settings`
  - テンプレートの新規作成・編集・複製・削除・状態切替
  - 行の「投稿作成」ボタンからテンプレート適用済み投稿作成画面へ遷移
- 投稿一覧: `/posts`
  - 「新規投稿」ボタンで最初の有効テンプレートを選択して `/posts/new?postSettingId=<id>` へ遷移
  - 有効テンプレートが存在しない場合は `/posts/new`（デフォルトフォーム）へ遷移
- 新規投稿: `/posts/new`（`postSettingId` は任意）

---

## 2. 投稿設定（テンプレート）の管理

### 2.1 新規作成

1. `/post-settings` で「新規投稿設定」をクリック。
2. 「基本情報」に以下を入力します。
   - 名称（必須）
   - スラッグ（必須、半角英数字とハイフンのみ、ユニーク）
   - 状態（有効 / 無効）
   - 説明（任意）
   - 詳細本文を有効化（任意、ON の場合は投稿詳細リッチテキストを許可）
3. 「カスタムフィールド定義」で必要なフィールドを追加します。
   - 追加 → フィールドタイプ選択 → ラベル・スラッグ・必須・説明・config/validation を設定
   - グループ / 繰り返しフィールドは子フィールドをツリー上で追加
   - 順序は上下ボタンで調整
4. 保存するとテンプレートが有効化され、一覧へ戻ります。

### 2.2 編集・複製・削除

- 編集: 行の「編集」から同じフォームを開き、設定を変更。
- 複製: 「複製」を押すと新しいスラッグ入力モーダルが開き、同じ定義で複製。
- 状態切替: トグルで有効⇄無効に変更。無効テンプレートは投稿新規作成で選択不可。
- 削除: テンプレートに紐づく投稿数が 0 の場合のみ実行可能。

### 2.3 既定テンプレート（`post-default`）

- テンプレート未指定時に利用する既定テンプレート。削除禁止。
- 無効化されるとテンプレート無し投稿が 409 で失敗します。
- 万が一欠損した場合は Runbook（`../api/docs/migrate-legacy-posts-runbook.md`）に従って復旧してください。

## 3. 投稿作成フロー

### 3.1 テンプレートあり投稿

1. 投稿設定一覧の行から「投稿作成」を選択、または `/posts/new?postSettingId=<id>` にアクセス。
2. 画面冒頭でテンプレート名称・スラッグ・説明を確認。
3. 共通フィールドを入力。
   - タイトル（必須）
   - カテゴリ（任意）
   - 状態（DRAFT / PUBLISHED / ARCHIVED）
   - 投稿日・公開日（初期値＝当日、自由入力と date input）
   - 詳細本文（常時リッチテキスト）
4. 「詳細ページを生成する」を ON にすると slug 入力欄が表示されます。`^[a-z0-9-]+$` でユニーク。
5. 下部にテンプレート定義どおりのカスタムフィールドが表示されます。必須チェックはテンプレートに従います。
6. 保存後はテンプレート名称付きトーストで結果が表示され、一覧へ戻ります。

### 3.2 テンプレート無し投稿（デフォルトフォーム）

1. 有効テンプレートが存在しない場合、または `/posts/new` に直接アクセスした場合に表示されます。
2. 画面冒頭に「デフォルト投稿フォーム」が表示され、テンプレート無しでも投稿可能である旨を案内。
3. 共通フィールドと詳細ページ設定のみを入力します。カスタムフィールド UI は非表示。
4. 送信時に `postSettingId` は空文字のまま送信され、API が `post-default` にフォールバックします。
5. 既定テンプレートが欠損または無効の場合:
   - API から 409（無効）または 424（欠損）が返り、エラートーストで復旧手順を案内します。
   - Runbook に従って復旧後、再送信してください。

### 3.3 投稿一覧からの導線

- `/posts` の「新規投稿」は最初の有効テンプレート ID をクエリに付けて遷移します。
- 有効テンプレートが 1 件もない場合はデフォルトフォームを表示し、「先に投稿設定を作成してください」というアラートを示します。

## 4. 運用チェックリスト

- [ ] `post-default` テンプレートが「有効」状態で存在する
- [ ] テンプレート更新後は関連投稿でフィールド表示崩れがないか確認する
- [ ] 監査ログ（Slack 連携）がテンプレート切替を記録している
- [ ] テンプレート無し投稿の E2E テストが通過している（`bun test:admin --grep "post without template"` と API 側ユニットテスト）
- [ ] Runbook 更新内容（`migrate-legacy-posts` 復旧手順）が最新である

---

## 5. トラブルシューティング

| 症状                                    | 対応                                                                                                                          |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| テンプレート無し投稿が 409 で失敗する   | `post-default` が無効です。投稿設定一覧で有効化するか、Runbook を参照して再作成してください。                                 |
| 424 が返る / テンプレートが見つからない | 既定テンプレートが欠損しています。Runbook に沿って再投入し、監視通知が閉じたことを確認。                                      |
| カスタムフィールドが表示されない        | テンプレートが無効、または `postSettingId` クエリが欠落しています。テンプレートを有効化し、投稿設定一覧から遷移してください。 |
| 詳細ページ slug が重複して保存できない  | slug はシステム全体でユニークです。`-1`, `-2` などを付けて再入力してください。                                                |
